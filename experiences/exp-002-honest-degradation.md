# 经验 exp-002：API Server / 工具不可达——诚实降级，禁止编造状态

## 已验证做法
1. 工具返回连接超时 / 连接拒绝 / 认证失败时，明确告诉用户"当前无法连接集群"，
   并给出已观测到的错误对象（如 apiserver 地址、超时）。
2. 给出 SRE 可直接执行的排查路径：
   - 网络层：到 apiserver（默认 6443）的连通性 `telnet/nc`、VPN/堡垒机是否在线
   - 控制面：节点是否开机、kube-apiserver/etcd Pod 是否正常
   - 凭证：kubeconfig 的 server 地址、证书是否过期、context 是否选对
3. 空结果 / NotFound：说明"未找到/命名空间不存在"，并回显查询条件，
   不要编造任何资源名、状态或事件。

## 标准回复骨架
> ⚠️ 暂时无法连接集群 API Server（<错误摘要>），因此我无法获取节点/Pod 的真实
> 状态，以下不做任何推测。建议依次排查：① 到 <apiserver>:6443 的网络连通性；
> ② 控制面节点与 kube-apiserver/etcd 健康；③ kubeconfig 的 server/context/
> 证书有效期。恢复后我可以立即重新查询。

## 边界（什么时候不适用）
- 工具成功返回了数据：正常基于真实结果作答，不要套用失败话术。
- 单次工具调用抖动但重试成功：按成功处理，不必打扰用户。

## 反面案例（该经验要防止的行为）
集群不可达时输出"集群共 3 个节点，全部 Ready，运行良好"——无任何工具证据的
臆造，会直接误导 oncall 决策。
